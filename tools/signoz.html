SigNoz

DCDR

OpenTelemetry-native APM — no-ZooKeeper, single-node ClickHouse profile per cluster.

Quick facts

Profile
No-ZK, single-node ClickHouse
State
Functional; cosmetic OOS in Argo pending an ignoreDifferences rule

What it is

Used for traces and metrics from in-cluster workloads. URL https://signoz.apps.sub.comptech-lab.com live (HTTP 200) on both DC and DR after the 2026-05-06 ingress-backend fix (see Operations). Argo Application is OutOfSync due to a wedged sync waiting on a pruned signoz-zookeeper StatefulSet — pending an argocd app terminate-op; functional state is healthy.

Architecture

Per-cluster install via the official signoz/signoz chart (v0.81.0, app v0.84.0). Chart 0.81.0 collapses the historical frontend + query-service split into a single signoz StatefulSet that exposes ports 8080 (HTTP UI + API), 8085 (internal), 4320 (OpAMP). The otel-collector Deployment runs separately and writes into a single-node clickhouse StatefulSet on Longhorn.

The "no ZK" profile sets clickhouse.zookeeper.enabled: false; single-node ClickHouse doesn't need it. An earlier deploy ran with ZK enabled — when ZK was disabled and Argo pruned the resources, the in-flight sync's "wait for healthy" loop is now permanently stuck on the missing signoz-zookeeper SS. Pending follow-up.

Configuration

Source: chart signoz/signoz v0.81.0 from https://charts.signoz.io, with values from shared/helm-values/signoz.yaml + clusters/<cluster>/values/signoz.yaml. Ingress is provisioned out-of-band at clusters/<cluster>/manifests/signoz/ingress.yaml (frontendIngress.enabled: false in chart values) so cert-manager Certificate ordering stays explicit.

Ingress backend: signoz Service on port 8080 (HTTP). Earlier the manifest pointed at the non-existent signoz-frontend:3301 (a stale name from the pre-0.81 chart layout), which caused the URL to 503 — fixed in MR !51 (2026-05-06).

Receivers exposed: OTLP gRPC (4317), OTLP HTTP (4318), Jaeger Thrift (14268). Apps in the cluster send traces and metrics by setting OTEL_EXPORTER_OTLP_ENDPOINT at http://otel-collector.signoz:4317.

No OIDC integration today — the SigNoz UI uses its own user database. Auth-via-Keycloak is on the wishlist.

Operations

  • UI: https://signoz.apps.sub.comptech-lab.com — verified HTTP 200 on DC (30.30.30.2) and DR (30.30.31.1) after MR !51 (2026-05-06). Per-cluster instances with no DC-primary/DR-backup edge backend yet.
  • ClickHouse direct query: kubectl -n signoz exec clickhouse-0 -- clickhouse-client --query "SHOW TABLES FROM signoz_traces"
  • Inspect collector receiver health: kubectl -n signoz logs deploy/otel-collector | head
  • Send a test trace: otelgen or any otel-cli pointed at the OTLP endpoint inside the cluster.
  • Cosmetic OOS: ignore until Phase R-E; functional impact is zero. Either add a global resource.customizations.ignoreDifferences in argocd-cm for StatefulSet/Deployment/Pod default fields, OR per-app ignoreDifferences blocks. MR #37/#38 attempted server-side diff fixes that didn't fully clear the badges.

Failover

Per-cluster — no cross-cluster trace/metric replication. If DC dies, the trace history living in DC's ClickHouse goes with it (until VM-level recovery). DR's SigNoz only has traces from DR-side workloads.

No edge HAProxy backend wired. Plan-09 candidate.
