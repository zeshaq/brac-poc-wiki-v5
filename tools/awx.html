What it is

One AWX instance per cluster, fronted by the edge HAProxy with DC primary + DR backup. Container images (awx, awx-ee, awx-operator) are ctr-imported on DR (and rke2-3) to avoid slow Quay.io pulls.

Architecture

Operator-driven: awx-operator (Helm chart 3.2.1) runs in awx namespace, watches an AWX CR, and reconciles it into the standard AWX deployment — awx-task (Celery worker), awx-web (Django + nginx), and an operator-managed Postgres-15-c9s StatefulSet. Each cluster has its own AWX with its own database; jobs and inventories on DC don't exist on DR.

OIDC: SOCIAL_AUTH_OIDC_* environment variables in the AWX CR's extra_settings point at the Keycloak awx confidential client. New users get auto-provisioned on first login. Group-to-team mapping rides through OIDC group claims.

Configuration

Source: clusters/<cluster>/manifests/awx/ + clusters/<cluster>/manifests/awx-operator/. Operator chart from https://ansible-community.github.io/awx-operator-helm.

The AWX CR specifies image_pull_policy, OIDC settings, and Postgres prereqs. To bypass slow Quay.io pulls on DR, the three core images are ctr import'ed onto DR nodes (and rke2-3) imperatively:

  • quay.io/ansible/awx:24.6.1
  • quay.io/ansible/awx-ee:24.6.1
  • quay.io/ansible/awx-operator:2.19.1
Long-term fix: the Nexus docker-proxy repo (planned).

Admin password: ~/cloud-init/awx-admin-password (DC) and ~/cloud-init/awx-rke2-admin-password (DR). The Keycloak awx client secret is a placeholder (awx-PLACEHOLDER) — rotation pending.

Operations

  • UI: https://awx.apps.sub.comptech-lab.com. After login, set up Inventories + Credentials + Project (git source) + Job Templates.
  • Operator status: kubectl -n awx get awx
  • Job runner pods: kubectl -n awx get pods -l app.kubernetes.io/name=awx-task
  • Restart workers after long-running stuck jobs: kubectl -n awx rollout restart deploy awx-task
  • Onboard a Keycloak user to TERRAKUBE_ADMIN/AWX_ADMIN groups: via Keycloak admin UI, then they get auto-provisioned with the right team on next login.

Failover

Edge HAProxy backend awx-rke2-be, DC primary + DR backup. Healthcheck: GET / matching ^(200|301|302|307|308)$ — 302 → /migrations_notran/ during migrations, 302 → /login/ at steady state.

Smoke test PASSED 2026-05-05: kubectl scale deploy awx-web awx-task --replicas=0 on DC → DR took over within ~14 s; restoring DC → traffic returned within ~42 s. AWX /api/v2/ping/ served continuously from DR backup throughout.

Caveat: no automatic AWX-database replication. Job history, inventories, schedules, secrets all live in each cluster's Postgres independently. After failover, DR is "blank-slate AWX" unless seeded from a DC backup.
