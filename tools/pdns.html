PowerDNS

Shared infra

Authoritative DNS for the lab zone — drives ACME DNS-01 challenges through cert-manager.

Quick facts

Form
VM on br30 at 160.30.63.133
Zone
sub.comptech-lab.com
API
Used by webhook-pdns for DNS-01

What it is

Wildcard *.apps.sub.comptech-lab.com → 160.30.63.134 covers the bulk of the platform. Explicit A records exist where wildcards don't synthesise (e.g. *.kafka.apps.sub.comptech-lab.com needs bootstrap.kafka... and broker-{0,1,2}.kafka... records explicitly because of RFC 4592 single-label matching).

Architecture

Single PowerDNS Authoritative server on the pdns VM at 160.30.63.133. Backend is sqlite3 (gsqlite3 launch backend, DB at /var/lib/powerdns/pdns.sqlite3). Cloudflare delegates the sub.comptech-lab.com zone here via NS records; Cloudflare itself is authoritative for the parent domain.

Two listening hostnames: ns1.sub.comptech-lab.com and ns2.sub.comptech-lab.com — both currently resolve to the same VM (no DR). The intra-cluster IP 30.30.30.0 (yes, the network address) is also the VM's br30 IP — moved from 30.30.30.1 on 2026-04-29 because it collided with HAProxy. Quirky but valid (RFC 1812).

Configuration

Server config: /etc/powerdns/pdns.conf on the VM. API key for the cert-manager-webhook-pdns lives at ~/cloud-init/pdns-api-key (chmod 600). Records are managed via the API for ACME challenges, and via sqlite3 directly for static A records (UPDATE records SET ... + bump the SOA serial).

Current zone (post 2026-05-06 round of cleanups):

  • Wildcard *.apps.sub.comptech-lab.com → 160.30.63.134 (haproxy)
  • Wildcard *.dr.apps.sub.comptech-lab.com → 160.30.63.138 (rke2-dr nginx-ingress passthrough)
  • Explicit A records: argocd.apps, awx.apps, gitlab.apps, terrakube.apps, terrakube-{api,reg}.apps, bootstrap.kafka.apps, broker-{0,1,2}.kafka.apps — all pointing at 160.30.63.134
  • NS + SOA for the zone; ns1 / ns2 A records → 160.30.63.133

Why explicit records when wildcard exists: DNS wildcard matches a single label per RFC 4592, so *.apps doesn't synthesise broker-2.kafka.apps; plus the existence of any subdomain of kafka.apps (an empty-non-terminal) blocks wildcard synthesis at broker-2.kafka.apps too.

Operations

  • Add an A record: 
    ssh ze@pdns 'sudo sqlite3 /var/lib/powerdns/pdns.sqlite3 \
  "INSERT INTO records(domain_id,name,type,content,ttl) \
   SELECT id,\"foo.apps.sub.comptech-lab.com\",\"A\",\"160.30.63.134\",300 FROM domains WHERE name=\"sub.comptech-lab.com\"; \
   UPDATE records SET content=REPLACE(content,\"<old serial>\",\"<new serial>\") \
   WHERE type=\"SOA\" AND name=\"sub.comptech-lab.com\";"
sudo pdns_control purge'
  • List zone: ssh ze@pdns 'sudo sqlite3 /var/lib/powerdns/pdns.sqlite3 "SELECT name,type,content FROM records ORDER BY name;"'
  • Test from outside: dig @160.30.63.133 +short <name> A
  • Purge response cache after a manual edit: sudo pdns_control purge

Failover

None today — single PowerDNS server. If the VM dies, the zone goes dark for everything past the wildcard's TTL (default 300 s).

Cloudflare's authoritative entry for sub.comptech-lab.com delegates here, so client-side resolution stops working. Mitigation: KVM snapshot of the VM + sqlite DB backup; rebuild path is create-pdns-vm.sh + restore pdns.sqlite3.
