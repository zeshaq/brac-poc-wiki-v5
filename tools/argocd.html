Foundation

Argo CD

DCDR

GitOps controller per cluster — reconciles the live state of DC and DR from a single Git repo.

Quick facts

Role
Continuous delivery / drift detection
Pattern
App-of-apps (root glob fans out per-app Applications)
Source repo
infra/gitops-rke2 on the lab GitLab
Scope
DC reconciles clusters/dc/apps/; DR reconciles clusters/dr/apps/

What it is

Argo CD runs in each RKE2 cluster as the GitOps controller and is the only way changes land in the platform. The DC and DR instances both watch the same monorepo (infra/gitops-rke2) but each scopes its reconciliation to its own clusters/<dc|dr>/apps/ path, while sharing values from shared/helm-values/.

App-of-apps with a root glob means adding a new app is a single-file change: drop a YAML under the right cluster path and Argo CD picks it up.

Architecture

Bootstrap is two-stage. The root Application (out-of-band kubectl apply at install time) lives in infra/argocd-bootstrap and points to the apps/ path of that repo. root-rke2 (DC) / root-rke2-dr (DR) is the per-cluster app-of-apps Application, sourced from infra/gitops-rke2; its directory.include globs pick up {argocd/projects/*.yaml,apps/*.yaml,infra/*.yaml,clusters/<cluster>/argocd/projects/*.yaml,clusters/<cluster>/apps/*.yaml,clusters/<cluster>/infra/*.yaml}. Adding a new app is a single-file YAML drop under the right path.

Argo Projects scope what each cluster's apps can deploy: rke2 (DC) and rke2-dr (DR) — copy-pasting an Application across clusters without flipping the project name fails the Application as InvalidSpecError (caught this way in MR !41).

Configuration

Apps generally use the two-source pattern: the chart from its upstream repo (e.g. https://codecentric.github.io/helm-charts for Keycloak), and value files from infra/gitops-rke2 via $values ref — layered as shared/helm-values/<app>.yaml + clusters/<cluster>/values/<app>.yaml.

Default sync policy across most apps: automated.prune=true, automated.selfHeal=true; sync options ServerSideApply=true, RespectIgnoreDifferences=true, CreateNamespace=true. Sync-wave annotation orders the rollout (foundation 0–4, vault 5, replication 6, app workloads 10+, smoke / tools 25+).

Three apps currently show cosmetic OutOfSync (keycloak-prereqs, terrakube-prereqs, signoz) — K8s API-server defaults that aren't in git. Functional impact: zero. Clearing this is a Phase R-E follow-up via global resource.customizations.ignoreDifferences in argocd-cm.

Operations

  • UI: https://argocd.apps.sub.comptech-lab.com (DC only).
  • Force a refresh: kubectl -n argocd patch app <name> --type=merge -p '{"operation":{"sync":{}}}'
  • Suspend automation temporarily (e.g. for destructive maintenance): kubectl patch app <name> --type=merge -p '{"spec":{"syncPolicy":{"automated":null}}}'
  • Add a new Application: drop YAML at clusters/<cluster>/apps/<name>.yaml; the root-rke2 glob picks it up on the next reconcile (3 min default).
  • Argo CD itself is bootstrap-installed via kubectl apply, not via Argo. Reconciles itself though (root → argocd Application).

Failover

Argo CD instances are cluster-local: each cluster's controller manages its own apps. There is no DC↔DR Argo failover by design — losing DC just means DC apps don't reconcile until DC's Argo is back. DR keeps reconciling independently.

UI access is DC-only at the edge; if DC is down, DR's Argo UI is reachable in-cluster but not edge-routed.
