What it is

A single all-in-one Splunk Enterprise instance running with the Splunk Free license — capped at 500 MB/day of indexed data, no clustering, no scheduled searches, no alerting. Useful for “spin up, kick the tyres, search some logs” workflows; not for any production load. SigNoz remains the cluster’s primary observability backend.

The instance lands as a Standalone custom resource managed by the Splunk Operator for Kubernetes, which provisions the underlying StatefulSet, two Longhorn-backed PVCs (one for /opt/splunk/etc config, one for /opt/splunk/var indexes), and a service exposing the Web UI (8000), HEC ingest (8088), management REST (8089), and the forwarder receiver (9997).

Architecture

One Standalone CR named stdln in namespace splunk. The operator reconciles it into a single-replica StatefulSet splunk-stdln-standalone, a headless service splunk-stdln-standalone-headless, and a regular service splunk-stdln-standalone-service. The StatefulSet pulls splunk/splunk:10.0.0 and runs splunk-ansible at first boot to render default.yml into the canonical config.

Free license + admin password arrive through spec.defaultsUrl: /mnt/splunk-defaults/default.yml on the Standalone CR, which mounts an imperative Kubernetes Secret splunk-default-yaml containing:

splunk:
  license_uri: Free
  password: <random 22-char alphanumeric>

The Secret is not in git (master copy at ~/cloud-init/splunk-admin-password, chmod 600 on dl385). Same imperative-Secret posture as DefectDojo. v0.2 swaps this for an ExternalSecret pulling from Vault secret/apps/splunk/*.

Volume name caveat: the operator auto-mounts its own internal Secret at /mnt/splunk-secrets (volume name mnt-splunk-secrets). User-defined volumes are mounted at /mnt/<volumeName>, so naming the user volume splunk-secrets collides with the operator’s mount. Ours is named splunk-defaults and mounts at /mnt/splunk-defaults.

Configuration

Source: chart splunk-enterprise 3.1.0 from https://splunk.github.io/splunk-operator/, with values from shared/helm-values/splunk.yaml + clusters/dc/values/splunk.yaml. Argo Application splunk at sync wave 12.

CRDs are not in the chart. Splunk publishes the operator CRDs as a separate release artifact (11 CRDs: Standalone, ClusterManager, IndexerCluster, SearchHeadCluster, MonitoringConsole, LicenseManager, IngestorCluster, ObjectStorage, Queue, plus deprecated ClusterMaster / LicenseMaster). Applied out-of-band with kubectl apply --server-side -f splunk-operator-crds.yaml.

The operator’s mandatory Splunk General Terms acknowledgment is set in chart values: splunk-operator.splunkOperator.splunkGeneralTerms: --accept-sgt-current-at-splunk-com.

Ingress is provisioned via the chart’s extraManifests at host splunk.apps.sub.comptech-lab.com → splunk-stdln-standalone-service:8000 on the cluster nginx ingress class. No edge HAProxy backend stanza is needed — it falls through the existing public-apps-https-be wildcard to the RKE2 nodes, like other cluster apps.

Operations

  • Web UI: https://splunk.apps.sub.comptech-lab.com · admin password at ~/cloud-init/splunk-admin-password (chmod 600 on dl385). HTTP 303 (redirect to login) is the expected pre-login response.
  • Verify license: kubectl -n splunk exec splunk-stdln-standalone-0 -- /opt/splunk/bin/splunk list licenser-groups -auth admin:<pw> — should show Free is_active:1.
  • Forwarder receiver: port 9997 is exposed in the Service but no edge HAProxy TCP frontend is wired today. v0.2 adds it if external forwarders are needed.
  • Sending events via HEC: port 8088 on the service. Token must be created in the Splunk UI first. No data-plane wiring yet — purely for ad-hoc testing.
  • Pull friction: the splunk:10.0.0 image is ~1.7 GB compressed and the lab outbound to docker.io is throttled — first pull on a fresh node takes ~2 hours. ctr image import of a podman-saved tarball does not bypass the kubelet pull unless you also tag the manifest digest (ctr image tag <repo>:<tag> <repo>@sha256:<digest>); kubelet’s IfNotPresent check requires RepoDigests to match.

Failover

None. v0.1 is DC-only. Splunk Free is single-instance by design — clustering and indexer replication are paid features. A DR pair would be two independent Splunks with no cross-cluster index replication unless we wire SmartStore + an S3-compatible object store (deferred — bigger lift than the v0.1 “few tests” scope warranted).
