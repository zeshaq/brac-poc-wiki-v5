What it is

Single-replica StatefulSet per cluster with its own Postgres StatefulSet. Realm is defined declaratively and loaded at startup. The codecentric chart's extraEnv is used to set KC_HOSTNAME to the public HTTPS URL and to drop the /auth URL prefix so the issuer lives at the root.

OIDC clients for the platform tools are pre-registered in the realm config; a few still hold placeholder secrets pending rotation.

Architecture

DC cluster                                  DR cluster
──────────                                  ──────────
StatefulSet keycloak-keycloakx (1 pod)      StatefulSet keycloak-keycloakx (1 pod)
  └─ realm comptech (pre-imported)            └─ realm comptech (pre-imported)
StatefulSet keycloak-postgres (1 pod)       StatefulSet keycloak-postgres (1 pod)

Edge HAProxy (160.30.63.134:443)
  ├─ keycloak-rke2-be
  │    server dc 30.30.30.2:80 check
  │    server dr 30.30.31.1:80 check backup
  └─ probe: GET /realms/master/.well-known/openid-configuration → 200|301|302|307|308

Clients (Vault, AWX, Terrakube, Argo CD, GitLab, Jenkins, Nexus, future apps)
  → https://auth.apps.sub.comptech-lab.com/realms/comptech

Each cluster runs a fully independent Keycloak — same realm definition pre-imported on both, same admin password expected (currently per-cluster passwords; aligning is a STATE.md TODO). Postgres is per-cluster; users created on DC don't exist on DR until a manual export/import. For platform tools whose user base is the same handful of operators, this is acceptable.

Configuration

Source of truth: shared/helm-values/keycloak.yaml (chart-level) and clusters/<cluster>/values/keycloak.yaml (per-cluster). Chart from https://codecentric.github.io/helm-charts, version 7.0.0.

Key extraEnv settings (came in via MR #26 + #27):

  • KC_HOSTNAME=https://auth.apps.sub.comptech-lab.com — pins the issuer to public HTTPS instead of in-cluster service URL.
  • http.relativePath=/ — drops the legacy /auth URL prefix; issuer lives at the root.
  • Realm comptech is loaded from a ConfigMap at startup via --import-realm.

OIDC clients in the realm:

  • vault — confidential, secret in Vault realm config (still vault-PLACEHOLDER; rotate via Keycloak admin UI)
  • argocd — confidential (argocd-PLACEHOLDER)
  • awx — confidential, used by AWX SOCIAL_AUTH_OIDC_* (awx-PLACEHOLDER)
  • terrakube — public client with PKCE, groups claim mapper
  • Future clients per overview — GitLab, Jenkins, Nexus to be wired

Admin credentials: ~/cloud-init/keycloak-{dc,dr}-admin.txt (chmod 600, per-cluster). Aligning the two via Vault-backed Secret is the long-term plan.

Operations

  • Admin UI: https://auth.apps.sub.comptech-lab.com/admin
  • Discovery doc: curl -sk https://auth.apps.sub.comptech-lab.com/realms/comptech/.well-known/openid-configuration | jq
  • Add an OIDC client: edit the realm CM in clusters/<cluster>/manifests/keycloak/realm-comptech-cm.yaml, commit, Argo applies — Keycloak picks up the new client on next start (or trigger a realm reimport via admin UI).
  • Realm export (for DR sync of users): kubectl -n keycloak exec keycloak-keycloakx-0 -- /opt/keycloak/bin/kc.sh export --realm comptech --file /tmp/realm.json
  • Smoke check OIDC discovery from a client side: in a Vault pod, curl -k https://auth.apps.sub.comptech-lab.com/realms/comptech/.well-known/openid-configuration should return 200 with "issuer": "https://auth.apps...".

Failover

Edge HAProxy backend keycloak-rke2-be with dc primary + dr backup; failover happens on health-check failure.

Smoke test PASSED 2026-05-05: kubectl scale sts keycloak-keycloakx --replicas=0 on DC → DR took over within ~13 s; restoring DC → traffic returned within ~18 s. The discovery doc was served continuously through the cutover.

Failover gotcha: if the same admin user logs in DC then fails to DR, their session cookie won't be valid (sessions are not replicated). They re-authenticate. Apps using token-based auth (Bearer JWT) survive failover because tokens are signed with the realm key, and the realm key is identical on both clusters (pre-imported from the same source).
