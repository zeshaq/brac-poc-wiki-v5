What it is

OWASP DefectDojo is a security findings management platform: it ingests scan output from many tools (Trivy, Trivy Operator, CycloneDX SBOM, Snyk, Bandit, Burp, ZAP, ...), de-duplicates findings, tracks them through engagements, and surfaces a single dashboard view. Here it is used as the aggregation layer above Trivy: the in-cluster operator on DC and DR both feed into it (via the trivy-defectdojo-bridge CronJob), and the Jenkins CI flow uploads per-build results from each pipeline.

Architecture

Five workload pods on DC: Postgres (StatefulSet), Valkey (StatefulSet), Django (Deployment, runs the web UI + REST API as uwsgi behind an nginx sidecar), Celery worker (Deployment, async tasks), Celery beat (Deployment, scheduler). The defectdojo-initializer Job runs Django migrations and creates the admin user on first install.

External traffic path: client → DNS defectdojo.apps.sub.comptech-lab.com → 160.30.63.134 (edge HAProxy) → SNI ACL routes to vm-tls-be → 127.0.0.1:8443 (HAProxy TLS terminate with wildcard cert) → defectdojo-rke2-be backend → DC RKE2 ingress on :80 → defectdojo-django Service (the nginx port).

v0.1 has DC-only DefectDojo. DR's Trivy Operator bridge CronJob talks to DefectDojo via the public edge URL (cross-cluster), not via in-cluster service DNS.

Configuration

Source: shared/helm-values/defectdojo.yaml. Cluster ingress carries nginx.ingress.kubernetes.io/ssl-redirect: false so the edge HAProxy → cluster :80 hop is not 308'd (same lesson as nexus). Body size uncapped, read/send timeouts bumped to 1800 s for large scan-report uploads.

Admin credential (v0.1 default-admin):

kubectl -n defectdojo get secret defectdojo \
  -o jsonpath='{.data.DD_ADMIN_PASSWORD}' | base64 -d

Then mirror to ~/cloud-init/defectdojo-admin-password (chmod 600). v0.2 hardens by pre-creating the Secret and rotating regularly.

API token for the bridge: log in as admin, top-right user menu → API v2 Key → Generate New Key. Then create the imperative Secret on each cluster:

kubectl -n trivy-defectdojo-bridge create secret generic defectdojo-api-token \
  --from-literal=token=<the-token-value>

Operations

  • UI: https://defectdojo.apps.sub.comptech-lab.com
  • Trigger immediate bridge run: kubectl -n trivy-defectdojo-bridge create job --from=cronjob/trivy-defectdojo-bridge bridge-now
  • List products: curl -k -H "Authorization: Token $T" https://defectdojo.apps.sub.comptech-lab.com/api/v2/products/?limit=10
  • Hand-upload a Trivy scan (CI flow): see docs/CI-TRIVY-DEFECTDOJO.md in gitops-rke2
  • Reset admin password: kubectl -n defectdojo exec deploy/defectdojo-django -c uwsgi -- python manage.py changepassword admin

Failover

v0.1 is DC-only. If DC's RKE2 cluster goes down, DefectDojo becomes unreachable until restored — DR has no DefectDojo and no replica of the Postgres data. Trivy Operator on each cluster keeps emitting CRDs locally; aggregation pauses. v0.2 adds a DR pair (with cross-cluster Postgres replication, e.g., the same logical-export pattern Vault uses) and an HAProxy backup server.
