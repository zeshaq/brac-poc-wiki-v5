What it is

OWASP DefectDojo is a security findings management platform: it ingests scan output from many tools (Trivy, Trivy Operator, CycloneDX SBOM, Snyk, Bandit, Burp, ZAP, ...), de-duplicates findings, tracks them through engagements, and surfaces a single dashboard view. Here it is used as the aggregation layer above Trivy: the in-cluster operator on DC feeds into it (via the trivy-defectdojo-bridge CronJob), and the Jenkins CI flow uploads per-build results from each pipeline.

Live as of 2026-05-06: 1 product (BFSI POC RKE2), 1 engagement (trivy-operator-rke2-dc), 213 tests, 1,800 findings (294 High, 549 Medium, 957 Low) — all from Trivy Operator's ConfigAudit reports. Vulnerability + SBOM ingest will populate once Trivy's image-scan Jobs finish their first DB pull.

Architecture

Five workload pods on DC: Postgres (StatefulSet), Valkey (StatefulSet), Django (Deployment, runs the web UI + REST API as uwsgi behind an nginx sidecar), Celery worker (Deployment, async tasks), Celery beat (Deployment, scheduler). The defectdojo-initializer Job runs Django migrations and creates the admin user on first install.

External traffic path: client → DNS defectdojo.apps.sub.comptech-lab.com → 160.30.63.134 (edge HAProxy) → SNI ACL routes to vm-tls-be → 127.0.0.1:8443 (HAProxy TLS terminate with wildcard cert) → defectdojo-rke2-be backend (DC primary, no DR backup yet, healthcheck GET /login) → DC RKE2 ingress on :80 → defectdojo-django Service (the nginx port).

The bridge runs in-cluster and talks to DefectDojo over the in-cluster Service DNS (http://defectdojo-django.defectdojo.svc:80) but with an explicit Host: defectdojo.apps.sub.comptech-lab.com header — Django's ALLOWED_HOSTS rejects the bare svc DNS.

v0.1 has DC-only DefectDojo. v0.2 adds a DR pair (with cross-cluster Postgres replication and an HAProxy backup server) and a DR-side bridge that talks to DC over the edge URL.

Configuration

Source: shared/helm-values/defectdojo.yaml. Cluster ingress carries nginx.ingress.kubernetes.io/ssl-redirect: false so the edge HAProxy → cluster :80 hop is not 308'd (same lesson as nexus). Body size uncapped, read/send timeouts bumped to 1800 s for large scan-report uploads.

Imperative Secrets (planted via kubectl create secret, NOT in git, masters at ~/cloud-init/defectdojo-{secrets.env,admin-password,api-token} chmod 600):

  • defectdojo (in defectdojo ns) — Django admin + secret-key + AES key. Chart's createSecret: false so Argo doesn't churn it on every sync.
  • defectdojo-postgresql-specific (in defectdojo ns) — Postgres user/admin/replication passwords.
  • defectdojo-valkey-specific (in defectdojo ns) — Valkey password.
  • defectdojo-api-token (in trivy-defectdojo-bridge ns) — DRF v2 token for the bridge.

Why imperative: chart-managed auto-generated passwords get re-rendered on every Argo sync, but Postgres locks the original password into its data dir on first init — so the running pod and the chart's Secret drift apart immediately. Pre-planting stable values side-steps that.

Bridge implementation: clusters/dc/manifests/trivy-defectdojo-bridge/configmap.yaml ships a Python script (image python:3.12-slim) that lists vulnerabilityreport + configauditreport + exposedsecretreport + sbomreport CRDs via the cluster API and POSTs each item individually to /api/v2/import-scan/. DefectDojo's "Trivy Operator Scan" parser does NOT handle kind: List wrappers — passing the bare kubectl get -o json blob produces 0 findings. Per-item upload is necessary. Each upload also passes product_type_name=Platform (auto-create-context requires it) and a tags=<prefix>:<ns>/<name> tag for traceability.

Operations

  • UI: https://defectdojo.apps.sub.comptech-lab.com — log in as admin with the password at ~/cloud-init/defectdojo-admin-password.
  • Read admin password from cluster: kubectl -n defectdojo get secret defectdojo -o jsonpath='{.data.DD_ADMIN_PASSWORD}' | base64 -d
  • Trigger immediate bridge run: kubectl -n trivy-defectdojo-bridge create job --from=cronjob/trivy-defectdojo-bridge bridge-now
  • Tail bridge logs: kubectl -n trivy-defectdojo-bridge logs -l job-name=bridge-now
  • List products via API: curl -k -H "Authorization: Token $T" https://defectdojo.apps.sub.comptech-lab.com/api/v2/products/?limit=10
  • Generate a new API token: kubectl -n defectdojo exec deploy/defectdojo-django -c uwsgi -- python manage.py drf_create_token admin
  • Reset admin password: kubectl -n defectdojo exec deploy/defectdojo-django -c uwsgi -- python manage.py changepassword admin
  • Hand-upload a Trivy scan (CI flow): see docs/CI-TRIVY-DEFECTDOJO.md in gitops-rke2

Failover

v0.1 is DC-only. If DC's RKE2 cluster goes down, DefectDojo becomes unreachable until restored — DR has no DefectDojo and no replica of the Postgres data. Trivy Operator on each cluster keeps emitting CRDs locally; aggregation pauses. v0.2 adds a DR pair (with cross-cluster Postgres replication, e.g., the same logical-export pattern Vault uses) and an HAProxy backup server.
