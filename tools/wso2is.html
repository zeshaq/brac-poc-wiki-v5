What it is

WSO2 IS is the second identity provider in the platform, deployed alongside Keycloak. The two have distinct, non-overlapping roles (codified in memory/project_idp_strategy.md and ADR-0019):

  • Keycloak — IdP for platform tools: Vault, AWX, Terrakube, Argo CD, GitLab, Jenkins, Nexus.
  • WSO2 IS — IdP for future user-deployed demo apps. The user runs apps that authenticate against this IS, separate from the operations tooling stack.

The two IdPs do not federate or trust each other. Don't wire WSO2 IS as an SP/IdP for Keycloak (or vice versa). When in doubt: new platform tool → Keycloak; new demo app → WSO2 IS.

This deployment supersedes the legacy VM-based wso2is (.7) + wso2is-dr (.27) pair that was decommissioned 2026-05-05 along with the rest of the WSO2 APIM stack. The Phase 3 install (2026-05-06) is a clean-slate rebuild on RKE2.

Architecture

DC cluster (rke2)
─────────────────
Deployment wso2is-identity-server (1 replica)
  └─ image docker.io/wso2/wso2is:7.2.0
  └─ embedded H2 file DB at /home/wso2carbon/wso2is-7.2.0/repository/database/
  └─ no clustering (single-replica), no persistence (PVC unwired)

Service wso2is-identity-server :9443 (HTTPS, self-signed wso2carbon.p12)

Ingress is.apps.sub.comptech-lab.com (nginx-ingress, cert-manager letsencrypt-prod)
  └─ backend-protocol: HTTPS  (nginx talks to IS on :9443 with TLS)
  └─ session affinity cookie  (paf cookie pinned to one replica)

Edge HAProxy (160.30.63.134:443)
  └─ SNI fallthrough → public-apps-https-be → rke2-{1,2,3}:443
     (no dedicated is-rke2-be backend yet; v0.2)

Future demo apps
  └─ register as Service Providers in IS via DCR or Console
  └─ OIDC issuer https://is.apps.sub.comptech-lab.com/oauth2/token

Single replica because: smoke test, embedded H2 (which doesn't tolerate concurrent writers), and simplicity. v0.2 will move to external Postgres + replicas≥2 once the demo apps actually exercise it.

Configuration

Source of truth: shared/helm-values/wso2is.yaml (chart-level values) + clusters/dc/values/wso2is.yaml (DC overlay, currently empty placeholder).

Key chart-value overrides:

  • deployment.image.registry: docker.io + deployment.image.repository: wso2/wso2is — public mirror, no WSO2 subscription required.
  • deployment.replicas: 1 + deploymentToml.clustering.enabled: false — single-pod, no kubernetes membership scheme noise.
  • deployment.persistence.enabled: false — chart's PV templates assume Azure/AWS RWX; not relevant for our Longhorn lab.
  • deployment.apparmor.enabled: false — RKE2 nodes don't ship the WSO2 default AppArmor profile.
  • deployment.pdb.minAvailable: 0 — 1 replica + minAvailable>=1 makes the PodDisruptionBudget block all drains.
  • deployment.ingress.commonAnnotations — adds cert-manager.io/cluster-issuer: letsencrypt-prod + nginx.ingress.kubernetes.io/backend-protocol: HTTPS.

What's NOT configured yet (v0.2 work):

  • External Postgres (5 datasources: identity, shared, user, consent, agentIdentity) — currently all H2.
  • Persistence on Longhorn RWO so config / users / SPs survive pod restart.
  • Custom keystore (currently the chart's default wso2carbon.p12 — issuer "WSO2 Carbon", suitable for testing but not for any external trust path).
  • Admin password rotation (currently admin/admin).
  • Edge HAProxy is-rke2-be backend (currently SNI-fallthrough to RKE2 ingress).

Operations

  • Console: https://is.apps.sub.comptech-lab.com/console (admin/admin)
  • Carbon Mgmt: https://is.apps.sub.comptech-lab.com/carbon (legacy admin UI)
  • OIDC discovery: curl -sk https://is.apps.sub.comptech-lab.com/oauth2/oidcdiscovery/.well-known/openid-configuration | jq
  • Pod logs: kubectl -n wso2is logs deploy/wso2is-identity-server -f --tail=200
  • Restart: kubectl -n wso2is rollout restart deploy/wso2is-identity-server — NB: with persistence disabled, all H2 data resets. Sleeping pods on node drain triggers the same.
  • Add a Service Provider (OIDC): Console → Applications → New → OIDC, fill in redirect URIs of the demo app, save. The chart's commonAnnotations on the Ingress include sticky-session affinity so the OAuth callback hits the same pod.
  • Add a user: Console → User Management → Users → Add — for first demo app onboarding. Multi-tenant isolation lives in /t/<tenant>/ URL prefix; default tenant is carbon.super.

Failover

None today. DC-only deployment, single replica. If the IS pod dies, demo apps that authenticate against it fail until the pod restarts. With persistence disabled, the restart returns a freshly-initialised IS — registered SPs and users are gone.

This is acceptable for smoke testing the first demo app's OIDC flow. Once the user starts onboarding real apps, v0.2 hardening (Postgres + persistence) is required so SP definitions and user data survive pod restarts.

No DR pair planned for v0.1. If demand grows, follow the Keycloak DC/DR pattern (per-cluster install, edge HAProxy DC-primary/DR-backup, identical realm/keystore on both sides).
