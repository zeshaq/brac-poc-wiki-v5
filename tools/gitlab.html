GitLab

Shared infra

Self-managed GitLab on a dedicated VM — hosts the GitOps repo and POC docs.

Quick facts

Form
VM on br30, not a per-cluster deployment
Hosts
infra/gitops-rke2, BRAC POC docs / wiki
Auth
Local admin (legacy WSO2 IS OIDC dead — see STATE notes)

What it is

GitLab is treated as shared infrastructure for the POC. There is no DC/DR pair for it — a single instance is sufficient for the demo's scope. CI on the GitOps repo gates merges.

Architecture

GitLab Omnibus 18.11.1 (CE) on a dedicated VM at 30.30.30.5 (br30). Single instance for the lab — there is no DC/DR pair. Hosted projects: infra/argocd-bootstrap (root Argo CD bootstrap), infra/gitops-rke2 (the application monorepo), brac/brac-poc-docs (issues/MRs only — wiki feature was decommissioned 2026-05-06; presentation surface moved to brac-poc-wiki-v5.pages.dev).

As of 2026-05-06, the same VM also hosts a GitLab Runner as a Docker container (gitlab/gitlab-runner:v18.11.2) so CI on the GitOps repo runs again. Runner uses Docker executor (host /var/run/docker.sock mount), concurrent=4, project-scoped to infra/gitops-rke2.

Configuration

Omnibus install — /etc/gitlab/gitlab.rb on the VM is the source of truth. The legacy omniauth_providers block for WSO2 IS is in place but dead (WSO2 IS VM was decommissioned 2026-05-05; the issuer endpoint 503s).

Runner: /etc/gitlab-runner/config.toml (chmod 600, root) holds the auth token (glrt-...) generated via the POST /api/v4/user/runners API. systemd-managed via /etc/systemd/system/gitlab-runner.service wrapping docker run --network host. NB: there is no gitlab-runner CLI on the host (deb install was abandoned because gitlab-runner-helper-images is 530 MB and the lab outbound is throttled to ~0.5 MB/min — the container ships them inside).

Auth tokens / PATs at ~/cloud-init/gitlab-md-pat (md@comptech.com.bd, used by automation) and ~/cloud-init/gitlab-root-pat (legacy; do not use).

Operations

  • UI: https://gitlab.apps.sub.comptech-lab.com
  • Runner status: ssh ze@30.30.30.5 'sudo systemctl status gitlab-runner; sudo journalctl -u gitlab-runner -n 50 --no-pager'
  • Restart runner (after config edit): sudo systemctl restart gitlab-runner
  • Add a new project-scoped runner: POST /api/v4/user/runners with runner_type=project_type, project_id=<id>, then add the [[runners]] stanza to config.toml with the returned auth token.
  • Backup: standard Omnibus gitlab-backup create targets the VM-local /var/opt/gitlab/backups/; ship to MinIO is a follow-up.

Failover

None. Single-instance, single point of failure for git history and CI. If the GitLab VM dies, the GitOps repo is gone (until VM restore from KVM snapshot or backup); both clusters keep running on whatever they last reconciled, but new MRs can't merge and Argo can't pick up changes.

Mitigation: regular gitlab-backup + KVM snapshots of the GitLab VM. Cloning the repo to /tmp/gitops-rke2 on the dl385 host gives a working copy too.
